# API Keys

Celune API keys let you connect external tools to your workspace - including your IDE via MCP, CI/CD pipelines, and your own integrations. This guide covers creating, managing, and securing your API keys.

For information on bringing your own AI provider keys (Anthropic, OpenAI, etc.), see the [BYOK guide](/guides/byok).

---

## Creating an API Key

1. Open the Celune dashboard and navigate to **Settings > API Keys**.
2. Click **New API Key**.
3. Enter a descriptive name - e.g., `claude-code-local`, `ci-pipeline`, `integration-test`.
4. Click **Create Key**.

> The key is shown **once** at creation. Copy it immediately and store it somewhere safe - Celune only stores a hashed version and cannot retrieve the plaintext key after this point.

---

## Using an API Key

Include your key in the `Authorization` header on every request:

```
Authorization: Bearer YOUR_API_KEY
```

For MCP connections, the key goes in your IDE's MCP configuration file. See the [MCP Setup Guide](/guides/mcp-setup) for details.

## BYOK (Bring Your Own Key)

Celune also supports **Bring Your Own Key** for AI providers. This is separate from Celune API keys - BYOK keys are your own AI provider credentials that Celune uses for agent conversations.

Supported providers:

| Provider          | Key Prefix | Default Model     |
| ----------------- | ---------- | ----------------- |
| **Anthropic**     | `sk-ant-`  | Claude Sonnet 4.6 |
| **OpenAI**        | `sk-`      | GPT-4o            |
| **Groq**          | `gsk_`     | Llama 3.1 70B     |
| **xAI (Grok)**    | `xai-`     | Grok-2            |
| **Google Gemini** | `AIza`     | Gemini 2.0 Flash  |
| **OpenRouter**    | `sk-or-`   | Auto              |

To add a provider key:

1. Go to **Settings > Provider Keys**.
2. Click **Add Provider Key**.
3. Paste your API key - Celune **auto-detects the provider** from the key prefix.
4. The key is encrypted before storage and never displayed again in full.

For full details, see the [BYOK Guide](/guides/byok).

---

## Security Best Practices

- **Never commit keys to source control.** Use environment variables or a secrets manager.
- **Never include keys in client-side code.** API keys are for server-side and CLI use only.
- **Audit regularly.** Review your active keys in **Settings > API Keys** and revoke anything unused.
- **Rotate keys periodically.** Create a new key, update your integration, then revoke the old one.
