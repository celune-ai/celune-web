# API Keys

Celune API keys let you connect external tools to your workspace, including your IDE via MCP, CI/CD pipelines, agent runners, and your own integrations. This guide covers creating, using, and securing keys.

For AI provider keys (Anthropic, OpenAI, and others), see the [BYOK guide](/guides/byok). For short-lived tokens that your app mints for its users, see [Embed Celune](/guides/embed).

---

## Creating an API Key

1. Open the Celune dashboard and navigate to **Settings > API Keys**.
2. Click **New API Key**.
3. Enter a descriptive name, such as `claude-code-local`, `ci-pipeline`, or `job-runner`.
4. Choose a scope: `read`, `write`, or `admin`.
5. Click **Create Key**.

> The key is shown **once** at creation. Copy it immediately and store it somewhere safe. Celune stores only a SHA-256 hash and cannot show the key again.

Self-hosted installs create keys the same way, in the web app you run.

---

## Key Format

Keys look like `celune_live_...` or `celune_test_...`. The middle part is the environment. Each key belongs to one workspace and one user.

A self-hosted install can change the first part with `CELUNE_API_KEY_PREFIX`. See [Self-Hosting](/guides/self-host).

---

## Using an API Key

Send the key in the `Authorization` header on every request:

```
Authorization: Bearer celune_live_...
```

The `X-API-Key` header is also accepted. Requests go to the [REST API v1](/api-reference/v1):

```bash
curl "https://app.celune.ai/api/v1/tasks?status=in_progress" -H "Authorization: Bearer $CELUNE_API_KEY"
```

For MCP connections, the key goes in your IDE's MCP configuration. See [MCP Setup](/guides/mcp-setup).

---

## Scopes

| Scope   | Allows                                                                  |
| ------- | ----------------------------------------------------------------------- |
| `read`  | Every `GET` route and read-only MCP tools                               |
| `write` | Everything in `read`, plus creating, updating, claiming, and completing |
| `admin` | Everything in `write`                                                   |

A request without the needed scope answers `403` with `Insufficient scope. Required: write`. Keys that run the [job queue](/api-reference/agent-protocol) need `write`.

---

## Rate Limits and Expiry

A key can carry a per-minute rate limit and an expiry date. Over the limit, requests answer `429` with `Retry-After` and `X-RateLimit-*` headers. Expired and revoked keys answer `401`.

---

## Security Best Practices

- **Never commit keys to source control.** Use environment variables or a secrets manager.
- **Never include keys in client-side code.** API keys are for servers, CLIs, and agents. For browsers, mint a [host JWT](/guides/embed) instead.
- **Use the smallest scope that works.** A dashboard that only reads tasks needs `read`.
- **Audit regularly.** Review active keys in **Settings > API Keys** and revoke anything unused.
- **Rotate keys periodically.** Create a new key, update your integration, then revoke the old one. Revoked keys stop working immediately.
